# Newsbot – Telegram-бот с саммари новостей (Elixir)

Минимальный long-polling Telegram-бот: по команде присылает саммари **сегодняшних**
статей с нескольких RSS-источников. Текст статьи чистится от рекламы и промо, затем
суммируется через **Google Gemini**, и каждая статья приходит отдельным сообщением.

## Команды

| Команда  | Что делает |
|----------|------------|
| `/start` | Показывает список доступных команд |
| `/apple` | Новости Apple – `iphones.ru`, `appleinsider.ru` |
| `/it`    | Новости IT – `xakep.ru`, `nuancesprog.ru` |

Формат поста:

```
1) Заголовок статьи

<саммари от Gemini>

Открыть оригинал   ← кликабельная ссылка
```

## Запуск

1. Elixir 1.15+ и `mix`.
2. Зависимости:
   ```bash
   mix deps.get
   ```
3. Запуск (токен от BotFather, ключ Gemini из Google AI Studio):
   ```bash
   TELEGRAM_BOT_TOKEN=123456:ABCDEF... GEMINI_API_KEY=AIzaSy... mix run --no-halt
   ```

`GEMINI_API_KEY` необязателен: без него вместо саммари присылается очищенная
выдержка из текста статьи.

## Переменные окружения

| Переменная           | Обязательна | Назначение |
|----------------------|:-----------:|------------|
| `TELEGRAM_BOT_TOKEN`  | да          | Токен бота от BotFather |
| `GEMINI_API_KEY`      | нет         | Ключ Google Gemini (AI Studio). Без него – выдержка вместо саммари |

> **Про ключи Gemini.** Google переводит API на новый формат ключей: ключи без
> ограничений (unrestricted standard keys) перестают приниматься примерно с
> **19 июня 2026**, а standard keys в целом – ориентировочно с **сентября 2026**.
> Подробности и актуальные даты – в [документации по ключам](https://ai.google.dev/gemini-api/docs/api-key).

## Как это устроено

- **`Newsbot.Bot`** – GenServer на long-poll (`getUpdates`). Маршрутизирует команды,
  рассылает посты через `sendMessage` с `parse_mode: HTML`.
  - Рассылка идёт в фоновом `Task`, по одному сообщению на статью.
  - **Флаг занятости (`busy`)**: пока идёт одна рассылка, новая команда вежливо
    просит подождать – чтобы параллельные запуски не делили лимит Gemini.
  - Сбой обработки одной статьи изолирован (`try/rescue`) и не прерывает остальные.
  - Отправка статьи повторяется при временном сбое Telegram (до 2 попыток).
- **`Newsbot.Digest`** – работа с лентами и Gemini:
  - Группы источников в `@feeds` (`:apple`, `:it`).
  - `todays_articles/1` загружает каждую ленту независимо (если лента недоступна –
    просто пропускается), фильтрует по сегодняшней дате, объединяет и сортирует.
  - `get_article_summary/2` загружает страницу, чистит рекламу и промо (Floki),
    суммирует через Gemini (по умолчанию `gemini-2.5-flash`, режим thinking отключён
    через `thinkingBudget: 0`).

### Чистка от рекламы

Два уровня:

1. **Парсинг** (`looks_like_junk?`) отбрасывает абзацы с явными маркерами: промо
   магазинов и каналов, призывы подписаться, формы регистрации/cookie, подписи к
   картинкам («Изображение: …», «Фото: …»), paywall-блоки. Дубли абзацев
   убираются (`Enum.uniq`).
2. **Промт Gemini** – резервный «ловец»: явно требует суммировать только содержание
   новости и игнорировать рекламу, интерфейс сайта, источники картинок, ссылки и
   повторы.

Если вылезает новый характерный мусор – достаточно дописать строку в список
маркеров `looks_like_junk?`.

### Лимиты Gemini и резервная отправка

Бесплатный тариф Gemini ограничен по числу запросов. Чтобы снизить риск потери
саммари:

- **Пауза между запросами** считается из локальной настройки `@gemini_rpm`
  (`gemini_pause_ms/0`): интервал ≥ 60 c / RPM держит частоту под лимитом при любом
  числе статей. `@gemini_rpm` – это **наш консервативный ориентир**, а не
  универсальный лимит: реальные лимиты зависят от тарифа, модели и проекта и видны
  в [AI Studio / документации](https://ai.google.dev/gemini-api/docs/rate-limits).
- **Повторная попытка при 429** с учётом `retryDelay` из ответа Google – переживает
  кратковременные всплески. Если исчерпан **дневной** лимит (ждать бесполезно) –
  сразу резервный вариант.
- **Резервный вариант**: если саммари получить не удалось, пост всё равно
  отправляется – с очищенной выдержкой из статьи. Сообщений «не удалось» бот не шлёт.

Настройки лимита и повторов – вверху `lib/newsbot/digest.ex` (`@gemini_rpm`,
`@max_retries`, `@max_retry_wait_ms`, `@default_retry_ms`).

## Известные ограничения / что можно добавить

- «Сегодня» определяется по дате из `pubDate` **в UTC**. Корректный учёт таймзоны
  (например, МСК) потребует `:tzdata` и разбора смещения – пока не сделано.
- Webhook вместо long-poll для продакшена.
- Кэш дайджеста с TTL (сейчас защита – только флаг занятости).
- Полнотекстовый `content:encoded` из RSS как источник тела статьи (есть не у всех
  лент) – мог бы убрать часть обвязки сайта на тех источниках, где он отдаётся.
- Новые разделы/источники – добавить запись в `@feeds`.
